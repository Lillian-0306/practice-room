# 會員用 Email＋密碼登入，不驗證信箱

Supabase 內建的寄信服務只寄給專案團隊成員、每小時 2 封，同學收不到登入信或驗證信。所以會員改用 Email＋密碼登入，並關掉信箱驗證：註冊時完全不寄信。Email 只當作帳號，不保證是本人的信箱。代價是會員不能自己重設密碼，忘記時要由網站管理員在 Supabase 後台重設；也可能有人用別人的 Email 註冊。之所以還是用 Email、不用自訂帳號名稱，是為了之後接上自己的寄信服務（SMTP）時，可以直接加回「忘記密碼」和信箱驗證，不用改帳號。

## Considered Options

- Email 連結登入（原本的做法）：內建寄信服務的限制下，只有網站管理員自己能用。
- Google 登入：不用寄信，但要另外設定 Google Cloud，先延後。
- 接自己的 SMTP：多一個服務要申請和維護，等真的需要讓會員自己重設密碼時再做。
